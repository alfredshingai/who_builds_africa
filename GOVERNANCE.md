# Governance

## Maintainer

- **Maintainer:** @alfredshingai (Alfred Shingai)
- **Role:** final review, releases, conflict resolution

Open to co-maintainers - nominate via Discussion.

## Roles

- **Contributor:** anyone submitting PR/issue/correction
- **Reviewer:** can approve PRs (requires 1 approval from reviewer != author)
- **Data Editor:** reviewer with domain expertise for historical evidence assessment
- **Maintainer:** merges, tags releases, manages Zenodo DOI

## Decision Making

- Lazy consensus on PRs (72h window if tagged `needs-decision`)
- Sensitive claims (defamation/political risk) require 2 reviewers
- License/governance changes require maintainer approval

## Review & Correction

See `REVIEW_POLICY.md` and `CORRECTIONS.md`. All public data is PR-reviewed before `main`. No direct push to `main` - branch protection enforces checks.

## Conflict Resolution

1. Discuss in PR/Issue 2. Request second reviewer 3. Maintainer decides, documented in `CHANGELOG.md`

## Code of Conduct

See `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1)

## Succession

If maintainer unavailable > 90 days, co-maintainer or community fork permitted (MIT/ODbL allow fork). Repository mirrored to Codeberg as backup (planned).
