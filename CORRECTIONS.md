# Corrections Policy

We correct transparently. Every change is auditable.

## How to request a correction

- Open Issue with template `correction` → include record ID, field, proposed value, source
- Or email maintainer
- PRs welcome with source-backed fix

## Process

1. Issue triaged within 7 days
2. Reviewer verifies source + evidence strength
3. If confirmed, PR merged; `change_history.csv` records: what/why/who/when/source/old→new
4. Next release notes list correction; previous releases remain archived

## History

No overwriting without audit trail. Previous values preserved in `change_history.csv` and git history.
